# 个人生活平台 — 页面设计规格 v1.1（日历 + 内容 + 理财复盘 + 板块预留）

- 版本：设计 v1.1（在 v1 已实现站点之上的迭代设计）
- 状态：**待用户确认**。确认后作为 builder 的实现依据。
- 上位文档：`docs/requirements.md`（v1 需求）、`docs/data-schema.md`（v1 数据格式）
- 本文档性质：**设计规格 + 实现约束**，不含 v1 的重复内容，只描述 v1.1 的增量
- 配套原型：`prototype/v1.1.html`（单文件、零外链、可直接双击打开的可点击高保真原型）

> 本设计的固定前提（不可违反）：零构建、零依赖、零外链、所有资源引用以 `./` 开头、`index.html` 仍为唯一页面、无框架。

---

## 1. 一句话设计目标

把现在「一个日历 + 一个当天记录面板」的单页，升级为**有板块导航的个人生活平台**：

> 打开首页 → 看今天（日历 + 今日内容）→ 点任意一天 → 看那一天的全部内容（生活记录 + 理财复盘）→ 点导航进「理财复盘」板块做复盘 → 其他板块先占位。

核心交互一句话：**日历是「时间轴」，板块是「内容维度」；点击日历上的某一天，右/下方内容区同时展示「那一天的全部维度内容」。**

## 2. 信息架构（IA）

### 2.1 板块清单

| 板块 | 路由 | 状态 | v1.1 交付 | 说明 |
|---|---|---|---|---|
| 首页 | `#/home` | ✅ 可用 | 今日概览 + 迷你月历 + 今日内容 | 新增 |
| 日历 | `#/calendar` | ✅ 可用 | 月历 + 当日全部内容（生活记录 + 理财复盘） | 由 v1 升级 |
| 理财复盘 | `#/finance` | ✅ 可用 | 复盘列表 + 月度汇总 + 按日详情 | 新增（本次核心） |
| 习惯打卡 | `#/habits` | 🔒 预留 | 占位页（含规划说明） | 只占位，不实现 |
| 健康 | `#/health` | 🔒 预留 | 占位页 | 只占位，不实现 |
| 关于 | `#/about` | ✅ 可用 | 数据来源、零依赖说明、发布说明链接 | 新增 |

**预留板块的呈现方式（重要，避免"点了没反应"）**：
预留板块**不做成死链接**（死链接会被当成 bug）。做成**可进入的占位页**：显示板块名、「规划中」徽标、一句话规划说明、以及「回到日历」按钮。这样导航栏结构一眼看全，又不欺骗用户。

### 2.2 导航结构

```
┌───────────────────────────────────────────────────────────────────────┐
│ 个人生活平台      [首页] [日历] [理财复盘] [习惯打卡🔒] [健康🔒] [关于]   │ ← 顶部一级导航（sticky）
└───────────────────────────────────────────────────────────────────────┘
```

- 一级导航固定 6 项，**预留项带锁形徽标 🔒 且 aria-label 后缀「规划中」**。
- 当前板块项有 `.is-current` 状态：**下边框加粗 + 顶部小圆点 + `aria-current="page"`**（不只靠颜色）。
- 导航本身用 `<nav aria-label="主导航">` + `<ul>`，每一项是 `<a href="#/xxx">`。**用 hash 路由，不用多页面**（保持 `index.html` 唯一）。

> 为什么用 hash 而不是多页面：`docs/requirements.md` §3 硬性规定"只有 `index.html` 一个 HTML 页面；v1 不做多页面、不做路由"。v1.1 要加板块又不违反这条，**hash 路由是唯一正解**（同一个文件内切换视图）。若用户希望改成多页面（`finance.html` 等），需先修改 requirements 的硬性约束，属于用户可选项，见 §11 待确认事项 Q3。

## 3. 三个可用页面的详细设计

### 3.1 首页 `#/home` —— 「今天」

目的是"打开就有用"，不要求用户先点日历。

```
┌─ 页头（标题 + 导航） ─────────────────────────────────────────────┐

│  今天有 1 条生活记录 · 1 篇理财复盘                                 │ ← 一句话摘要
├──────────────────────────────┬───────────────────────────────────┤
│  今日内容                     │  本月速览（迷你月历）              │
│  ┌ 生活记录 ────────────┐    │  ┌──┬──┬──┬──┬──┬──┬──┐          │
│  │ ● 和家人视频通话      │    │  │..│..│..│..│..│..│ 1│          │
│  │   #家人               │    │  │ ●│ ●│  │  │  │  │  │          │
│  └──────────────────────┘    │  ...                              │
│  ┌ 理财复盘 ────────────┐    │  └──┴──┴──┴──┴──┴──┴──┘          │
│  │ 今日盈亏 +128.50      │    │  「本月 4 个有记录日 / 2 个复盘日」 │
│  │   看点：…             │    │  [ 打开完整日历 → ]                │
│  └──────────────────────┘    │                                   │
│                              │  快速跳转                          │
│                              │  [ 日历 ] [ 理财复盘 ]              │
└──────────────────────────────┴───────────────────────────────────┘
```

- 迷你月历**不可点击**（避免和完整日历的交互打架），只作概览 + 一个「打开完整日历」按钮跳到 `#/calendar` 并选中今天。
- 今日内容区**复用**完整日历页的内容卡片组件（同一个渲染函数），不重复实现。

### 3.2 日历页 `#/calendar` —— 日历 + 当日内容（本次最关键的一页）

在 v1 布局（左日历 / 右面板）基础上的**唯一结构性改动**：右侧面板从「只有生活记录」升级为**分维度内容栈**。

```
┌─ 页头（标题 + 导航） ─────────────────────────────────────────────┐
├─ 月份条：‹ 上月 │ 2025 年 6 月 │ 下月 › │ 回到今天 ────────────────┤
├───────────────────────────────┬───────────────────────────────────┤
│  一 二 三 四 五 六 日          │  2025-06-14  星期日                │ ← 选中日
│  ┌──┬──┬──┬──┬──┬──┬──┐      │  生活记录 2 条 · 理财复盘 1 篇       │ ← 计数摘要
│  │ 1│ 2│ 3│ 4│ 5│ 6│ 7│      │  ───────────────────────────────  │
│  ├──┼──┼──┼──┼──┼──┼──┤      │  ▸ 生活记录                        │ ← 维度分组头
│  │ 8│ 9│10│11│12│13│●14│←选中 │    ● 晨跑 5 公里                   │
│  │  │▲●│  │  │  │  │▲ │      │      感觉不错…  #健康 #运动        │
│  └──┴──┴──┴──┴──┴──┴──┘      │    ● 读《人月神话》30 页            │
│                               │  ▸ 理财复盘                        │
│  图例：● 有生活记录             │    ┌ 今日盈亏 +320.00 (+1.86%) ┐    │
│        ▲ 有理财复盘             │    │ 操作：买入 沪深300ETF      │    │
│        ▲● 两者都有（双标记）    │    │ 心得：…                    │    │
│                               │    │ 标签：#调仓 #复盘           │    │
│                               │    └───────────────────────────┘    │
│                               │    [ 在理财复盘板块中查看 → ]        │
└───────────────────────────────┴───────────────────────────────────┘
```

**关键设计点：**

1. **日历格新增第二种标记：理财复盘**。
   - 有生活记录 = 实心圆点（**沿用 v1 现有样式**，不改）。
   - 有理财复盘 = **实心上三角 ▲**（放在圆点**右侧**，两者并排）。
   - 两者都有 = **圆点 + 三角同时出现**（"▲●" 或 "●▲"，实现规定为**左圆点右三角**）。
   - 现状 v1 是"圆点**居中**"，v1.1 改为 **`flex-direction: row` 的标记行**。新增元素**只加不减**：即无理财复盘时仍渲染一个圆点，视觉与 v1 基本一致（只是圆点从"独立一行居中"变成"标记行居中"，肉眼几乎无差）。
   - 理由：只有圆点、三角、圆点+三角三种组合，**不依赖颜色也完全可辨**，满足 requirements §3.2 B 与 §3.5 的可访问性红线。

2. **右侧面板 = 分维度内容栈**，维度分组头（`▸ 生活记录` / `▸ 理财复盘`）带该维度条目数。
   - 某维度当天为空 → 该分组**不渲染**；两个维度都为空 → 显示统一空态「这一天还没有任何记录」+ 新增方式提示。
   - **不残留上一天内容**（沿用 v1：每次整体重建 `innerHTML`）。
   - 分组顺序固定：生活记录 → 理财复盘（与导航顺序一致，可预期）。

3. **交互不变**：点击日格 = 选中该日；键盘方向键在日历内导航、Enter/Space 选中；PageUp/PageDown 翻月；`回到今天` 选中今天。全部沿用 v1 已有实现，**不重写**。

4. **月份条保持独立于页头**（v1 把它放在页头里；v1.1 因为页头要塞导航，把月份条下移成日历页内的工具条）。这是本设计对 v1 布局的唯一"位移"，不含样式重写。

5. **窄屏（≤720px）**：日历与内容面板**上下堆叠，日历在上**（沿用 v1 断点，不新增断点）。

```
┌─ 页头（标题 + 导航，理财复盘为当前项） ──────────────────────────┐
├─────────────────────────────────────────────────────────────────┤
│  理财复盘                          数据来自 ./data/finance.json  │
├─────────────────────────────────────────────────────────────────┤
│  ┌ 本月汇总 ────────────────────────────────────────────────┐   │
│  │  6 月累计盈亏  +1,240.00   胜/负天数  3 胜 1 负            │   │
│  │  复盘 4 天 · 最近一次 2025-06-20                          │   │
│  └──────────────────────────────────────────────────────────┘   │
│  月份切换：‹ 上月  2025 年 6 月  下月 ›                          │
├─────────────────────────────────────────────────────────────────┤
│  2025-06-20  星期日   今日盈亏 +520.00 (+2.10%)                  │ ← 复盘卡
│  ┌ 操作记录 ────────────┐  ┌ 心得 ──────────────────────────┐   │
│  │ 卖出 中证红利ETF      │  │ 按纪律执行，没有追高。          │   │
```

- **列表按日期倒序**（最新复盘在最上）：理财复盘的使用场景是"回顾最近"，与生活记录"按数组顺序"不同。

- **盈亏的正负不只靠颜色**：正数**带 `+` 号**、负数**带 `−` 号**（且符号在数字前），颜色只是辅助。盈亏未知时显示 `—`（"未记录"），不显示 0，避免误导。

- **该板块不做图表**（零依赖下用原生 SVG 画图是 v3 范围，见 `docs/requirements.md` §7 v3）。v1.1 只用文字 + 数字汇总。

## 4. 视觉与样式规格（增量，不改现有风格）

**方向：延续现有清爽风格，只加"导航 + 卡片层级 + 维度分组"。**（理由：v1 的 430 行样式已验证可用，重写风险高、收益低；v1.1 的目标是加板块，不是换皮。）

### 4.1 复用现有 CSS 变量（新增变量一律少而必要）

沿用 `assets/style.css:7-64` 的既有变量，**新增**：

```css
--finance: #1f7a52;        /* 理财维度主色（与 --dot 蓝、--dot-alt 紫区分） */
--finance-soft: #e6f4ec;
--gain: #b3261e;           /* 盈：这里刻意用"红涨"，因为是中文语境 */
--loss: #1f7a52;
--reserved: #8a93a0;       /* 预留/占位板块 */
```
（暗色主题下各自给一套，值与现有暗色变量风格一致。）

> **配色提醒（待确认 Q1）**：中文语境传统是**红涨绿跌**；但国际通行与部分软件是绿涨红跌。原型按**红涨绿跌**实现，并在卡片上始终带 `+`/`−` 符号与文字（"盈"/"亏"），所以即使配色不符合你的习惯，信息也不会读错。若你要绿涨红跌，只需换两个变量值。

### 4.2 新增组件清单（给 builder 的精确清单）

| 组件 | 类名 | 用途 |
|---|---|---|
| 顶部导航 | `.topnav`、`.topnav-list`、`.topnav-item`、`.topnav-link`、`.is-current`、`.nav-lock` | 6 项一级导航 |
| 页面容器 | `.view`、`.view[hidden]` | hash 路由的视图切换（`hidden` 属性 + CSS，不用 display 内联） |
| 内容维度分组 | `.day-group`、`.day-group-head`、`.day-group-count` | 右侧面板「生活记录 / 理财复盘」分组 |
| 复盘标记 | `.day-mark-row`、`.day-tri` | 日历格内的 ▲ |
| 复盘卡 | `.review-card`、`.review-card-head`、`.review-metrics`、`.review-metric`、`.review-body`、`.review-actions` | 理财复盘板块 |
| 盈亏数字 | `.pnl`、`.pnl-gain`、`.pnl-loss`、`.pnl-flat` | 带正负号的盈亏 |
| 汇总条 | `.summary-bar`、`.summary-item`、`.summary-value` | 月度汇总 |
| 占位块 | `.reserved-panel`、`.badge-reserved` | 预留板块与「规划中」徽标 |
| 首页 | `.home-grid`、`.home-today`、`.mini-calendar`、`.quick-jump` | 首页两块 |

### 4.3 状态与可访问性（**红线，必须全部满足**）

1. **今日 / 选中 / 有生活记录 / 有理财复盘 四种状态互不冲突，且不只靠颜色。**
   - 今日：加粗边框 + `今`角标（宽屏）/ 下划线（≤720px）——沿用 v1。
   - 选中：实心底 + 内描边 + `aria-pressed="true"`——沿用 v1。
   - 有生活记录：双线边框 + 圆点——沿用 v1。
   - 有理财复盘：▲ 图形 + `aria-label` 追加「有理财复盘」——新增。
2. **日格的 `aria-label` 更新**（唯一必须改的可访问性文案）：
   - v1：`2025 年 6 月 14 日，有记录，已选中`
   - v1.1：`2025 年 6 月 14 日，有生活记录，有理财复盘，已选中`
   - 规则：两个维度都无 → `无记录`；仅一个 → `有生活记录` / `有理财复盘`；两个都有 → `有生活记录，有理财复盘`。
3. 导航项：`aria-current="page"`；预留项 `aria-label="习惯打卡（规划中）"`。
4. 键盘：导航是原生 `<a href="#/...">`，天然 Tab 可达 + Enter 可激活；**hash 变化后把焦点移到新视图的 `<h2 tabindex="-1">`**，否则读屏用户不知道页面变了。
5. 对比度满足 WCAG AA；`--finance` / `--gain` / `--loss` 在亮暗两种主题下都需实测（原型已按 AA 选值）。
6. **控制台 `console.error` 必须为空**（v1 验收 A9 的延续）。

## 5. 交互规格

### 5.1 hash 路由

| hash | 视图 | 说明 |
|---|---|---|
| 空 / `#/` / 未知 | 首页 | 未知 hash 一律**回落到首页**并 `replace` 掉，不报错、不白屏 |
| `#/home` | 首页 | |
| `#/calendar` | 日历 | |
| `#/calendar/2025-06-14` | 日历 + 选中该日 | **可选增强**：深链到某天，方便从理财复盘卡跳回 |
| `#/finance` | 理财复盘 | |
| `#/habits`、`#/health` | 预留占位 | |
| `#/about` | 关于 | |

规则：
- 监听 `window.addEventListener('hashchange', route)`；首屏 `DOMContentLoaded` 后主动 `route()` 一次。
- 切视图 = 给非当前 `.view` 加 `hidden`，当前视图移除 `hidden`。**不销毁 DOM**（日历状态得以保留，切回来不用重渲染）。
- 路由函数**不得抛异常**（未知 hash 回落），保证 A14 的"绝不白屏"精神延续。

### 5.2 数据加载（v1.1 关键：**两个数据源，失败互不影响**）

| 数据源 | 用途 | 失败后果 |
|---|---|---|
| `./data/entries.json` | 生活记录 | 日历仍可翻月；生活记录分组显示错误态；**理财复盘不受影响** |
| `./data/finance.json` | 理财复盘 | 日历不显示 ▲；理财复盘分组/板块显示错误态；**生活记录不受影响** |

- 两个 `fetch` **并行发起**，各自独立 `catch`，各自独立的 `state`（`loading | ok | failed`）。
- 页脚汇总行分别报告：`生活记录 6 条 · 理财复盘 4 篇 · 覆盖 2 个月份`；任一失败则该项以错误色 + 明确文案呈现。
- **数据错误不得导致整页白屏**（沿用并发扬 `docs/data-schema.md` §4 的精神）。

### 5.3 `file://` 降级（**本次的体验重点**）

v1 遗留痛点：双击 `index.html` 时 `fetch` 被浏览器拦截，页面只剩错误提示。

**v1.1 的处置（不违反零依赖、不新增数据副本）：**
1. 仍以 `fetch('./data/*.json')` 为**唯一生产路径**（Pages 上必须是它）。
2. 若 `location.protocol === 'file:'`**或** fetch 失败，则判断 `window.LIFE_SAMPLES`（来自 `./assets/data-samples.js`）是否存在：
   - 存在 → 用示例数据渲染，并在页面顶部显示一条**不可忽略的横幅**：
     > 「当前为本地预览模式：正在显示 `assets/data-samples.js` 中的示例数据，**不是** `data/entries.json` 的真实数据。请用本地 HTTP 服务打开以查看真实数据。」
   - 不存在 → 保持 v1 的错误提示（明确告诉用户起本地服务）。
3. `data-samples.js` 是**预览专用**文件，与生产数据**同源同 schema**，在 README 中明确说明"这是预览用副本，真实数据以 `data/*.json` 为准"。

> **待确认 Q2**：这一步略微突破"不得内置重复的备用数据副本"的措辞。我的判断是：条文原意是防止"运行时用内置数据冒充真实数据"，而这里①只在 `file://` 下触发、②有显式横幅声明、③生产路径不变。若你要严格守条文，删掉该文件与 §5.3 第 2 步即可，其余设计不受影响（代价是双击打开仍然看不到内容）。

### 5.4 新增/编辑记录（v1.1 仍不做）

## 6. 数据规格

### 6.1 `data/entries.json` —— **完全不变**

v1.1 不改 `entries.json` 的任何字段、不递增 `schemaVersion`（仍是 `1`）。理由：生活记录维度与 v1 语义完全一致，改了会破坏 v1 已验证的实现与文档。

### 6.2 `data/finance.json` —— **新增，v1.1 新定义**

```json
{
  "schemaVersion": 1,
  "updatedAt": "2025-06-20",
  "reviews": [
    {
      "date": "2025-06-14",
      "pnl": -180.0,
      "pnlPct": -0.92,
      "actions": [
        "买入 沪深300ETF 1000 份 @ 3.842",
        "卖出 中证红利ETF 500 份 @ 1.276"
      ],
      "note": "上午追高了一笔，午后回落。教训：不在情绪里下单。",
      "tags": ["追高", "教训"]
    }
  ]
}
```

字段定义（**权威**）：

| 字段 | 层级 | 必填 | 类型 | 约束 | 缺省行为 |
|---|---|---|---|---|---|
| `schemaVersion` | 顶层 | ✅ | integer | 固定 `1`；缺失/非整数 → `console.warn` 后仍按 v1 解析 | 同左 |
| `updatedAt` | 顶层 | ❌ | string | `YYYY-MM-DD` | 缺失 → 页脚不显示该行 |
| `reviews` | 顶层 | ✅ | array | 元素为 review；缺失或非数组 → 视为 0 篇 + 提示「数据格式不符合预期」 | 同左 |
| `date` | review | ✅ | string | `YYYY-MM-DD`，必须真实存在 | 非法 → **跳过该条** + `console.warn`（含下标） |
| `pnl` | review | ❌ | number \| null | 当日盈亏（元），可负；`null`=未记录 | 缺失/非数字 → 记 `null`，界面显示 `—`，**不跳过** |
| `pnlPct` | review | ❌ | number \| null | 当日盈亏百分比，如 `1.86` 表示 +1.86% | 同上 |
| `actions` | review | ❌ | array\<string\> | ≤20 条，每条 1–200 字符，空串过滤 | 缺失/非数组 → `[]`，不渲染操作区 |
| `note` | review | ❌ | string | ≤5000 字符，可多行 | 缺失 → 不渲染心得区 |
| `tags` | review | ❌ | array\<string\> | ≤12 个，每个 1–20 字符，不含 `#` 与空白，去重 | 缺失 → `[]` |

**"整条记录算不算有效"的判定**：只要 `date` 合法，就是一个有效复盘日（哪怕 `pnl`、`actions`、`note` 全空），面板显示「当日盈亏未记录」。这与 `entries.json` 要求 `title` 必填不同——因为复盘的核心是"我复盘了哪一天"，而不是"我赚了多少"。

**同一天多条**：允许；板块内按 `date` **倒序**、同日按数组原顺序展示。

**约束沿用 v1**（`docs/data-schema.md` §2.3）：日期按字符串或本地构造 `new Date(y, m-1, d)` 处理，**严禁 `new Date("YYYY-MM-DD")`**；纯 JSON、无注释、无尾随逗号；UTF-8 无 BOM。

### 6.3 `assets/data-samples.js` —— 预览专用（见 §5.3）

```js
window.LIFE_SAMPLES = { entries: { schemaVersion: 1, entries: [ /* 同 entries.json schema */ ] },
                        finance: { schemaVersion: 1, reviews: [ /* 同 finance.json schema */ ] } };
```

## 12. 一句话总结

v1 是「一个日历 + 一天的记录」；v1.1 是**「一个带板块导航的平台，日历是统一的时间入口，点任意一天就能看到那一天的所有维度内容，其中理财复盘是第一个真正做实的板块，其余板块先占位不骗人」**。
